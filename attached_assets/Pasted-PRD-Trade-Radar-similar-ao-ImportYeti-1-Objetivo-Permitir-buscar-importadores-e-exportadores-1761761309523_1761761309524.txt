PRD — “Trade Radar” (similar ao ImportYeti)
1) Objetivo

Permitir buscar importadores e exportadores e visualizar seus embarques marítimos (histórico, KPIs, gráficos, top parceiros/portos/países/HS) a partir de arquivos Excel/CSV ingeridos apenas pelo administrador. Os dados ficam persistidos em Postgres.

2) Personas

Analista/Compras: descobre fornecedores e volume por período.

Trader/Comex: filtra por HS/porto/país e analisa sazonalidade.

Diretoria: acompanha indicadores (embarques/mês, TEUs, peso).

3) Requisitos Funcionais (v1)

Busca global (barra central) por nome de empresa (importador/exportador); fuzzy match tolerante a variações (“LTDA”, “CO.” etc.).

Página da empresa com:

KPIs: nº embarques, TEUs, peso bruto total, nº parceiros.

Gráfico “Shipments over time” (mensal).

Top parceiros (importer↔exporter), top países de origem, top portos destino, top HS Codes.

Tabela filtrável de embarques (período, HS, país/porto).

Exportar CSV filtrado.

Página de resultado de busca (lista de empresas encontradas por similaridade).

Somente Admin:

Área /admin protegida por login (role=admin).

Upload de Excel/CSV.

Visualizar histórico de ingestões (status, linhas OK/erro, log).

Reprocessar/descartar uma ingestão.

Deduplicação & Normalização na ingestão:

Canonização de nomes de empresas (normalização + pg_trgm).

Mapeamento de países para ISO-3166 e de portos (preferir UN/LOCODE).

Geração de chave única de embarque (hash determinístico).

Autorização:

Visitantes/usuários: navegam e pesquisam.

Apenas admin vê e usa /admin/upload.

4) Requisitos Não-Funcionais

Postgres 14+ com extensões pg_trgm e (opcional) postgis.

Resposta de busca < 300 ms (com índices e cache).

Uploads até 50 MB por arquivo (configurável).

Observabilidade básica: logs de ingestão e contador de erros por arquivo.

5) Fluxos Principais
5.1 Busca

Usuário digita “ACME” → endpoint /search?q=acme.

Retorna empresas (importers/exporters) por similaridade trigram (score).

Ao clicar numa empresa → /company/:id.

5.2 Página da Empresa

Carrega KPIs e séries temporais por company_id.

Lista “Top partners / countries / ports / HS”.

Tabela de embarques com paginação e filtros.

Botão Export CSV do resultado filtrado.

5.3 Upload (somente admin)

Admin acessa /admin/upload.

Envia Excel/CSV. O backend:

Salva o arquivo (S3 ou disco).

Cria registro em ingestions (status='queued', checksum).

Dispara job de ETL assíncrono.

Job lê planilha (biblioteca xlsx/pandas), valida cabeçalhos, normaliza colunas, e executa:

UPSERT de empresas/portos/HS em suas dimensões.

INSERT em shipments com shipment_uid (hash) + ON CONFLICT DO NOTHING para dedup.

Atualiza contadores rows_total/ok/failed e status=done|failed.

Armazena amostras de erros em ingestion_errors.

Importante: o usuário final do app NÃO vê /admin e NÃO tem acesso a upload.

Embarques (fato)
create table shipments (
  id bigserial primary key,

  shipment_uid text not null,          -- hash determinístico para dedup
  shipment_no text,                    -- EMBARQUE/BL
  ets date,
  eta date,
  cargo_type text,

  importer_id bigint references companies(id),
  exporter_id bigint references companies(id),
  forwarder_id bigint references companies(id),
  carrier_id bigint references companies(id),

  loading_port_id bigint references ports(id),
  discharge_port_id bigint references ports(id),
  destination_port_id bigint references ports(id),

  hs_code text references hs_codes(code),

  containers numeric,

  ingestion_id bigint references ingestions(id), -- rastreabilidade
  raw_row_hash text,                             -- md5 da linha original (auditoria)
  created_at timestamptz default now()
);

create index on shipments (eta, ets);
create index on shipments (importer_id);
create index on shipments (exporter_id);

Como gerar shipment_uid

Use um hash estável com os principais campos (ignorando diferenças cosméticas):

shipment_uid = md5(
  upper(trim(shipment_no)) || '|' ||
  coalesce(to_char(ets,'YYYY-MM-DD'),'') || '|' ||
  coalesce(to_char(eta,'YYYY-MM-DD'),'') || '|' ||
  importer_id || '|' || exporter_id || '|' ||
  loading_port_id || '|' || coalesce(destination_port_id, discharge_port_id)
)


No worker (ETL), calcule isso após resolver company_id e port_id.

(Opcional) Visualizações/materialized views
create materialized view mv_company_monthly as
select
  c.id as company_id,
  date_trunc('month', coalesce(s.ets, s.eta))::date as month,
  count(*) as shipments,
  sum(coalesce(s.teus,0)) as teus,
  sum(coalesce(s.gross_weight_kg,0)) as gross_weight_kg
from shipments s
join companies c on c.id in (s.importer_id, s.exporter_id)
group by 1,2;

create index on mv_company_monthly (company_id, month);

ETL — Deduplicação e Normalização
Regras de normalização

Empresa: normalize(name) → UPPER → remove pontuação e sufixos frequentes (LTDA/LTD/INC/LLC/SA/CO/IND/EIRELI/ME/EPP/“.”/“,”/parênteses).

Países: mapear nomes (ex: “Brasil”, “BRASIL”, “BRAZIL”) → BR. Tabela countries como dicionário.

Portos: tentar match por UN/LOCODE quando existir; senão, por nome normalizado + país. Guardar aliases encontrados.

Datas: parse ETS/ETA (DD/MM/AAAA, MM/DD/YYYY, etc.).

Numéricos: converter TEUs, containers, gross_weight_kg, volumes.

Deduplicação

Empresas:

Buscar por normalized_name com pg_trgm, similarity > 0.9.

Se achar, usar company_id; se não, criar e registrar company_aliases.

Portos:

Se UN/LOCODE presente → unique.

Senão, buscar por (normalized_name, country) com trigram; se ~igual, reutiliza; senão cria.

Embarques: shipment_uid único (ver fórmula acima) + ON CONFLICT DO NOTHING.

Validação mínima por linha

Pelo menos UM entre importer_name e exporter_name.

Pelo menos UM entre loading_port e discharge/destination_port.

Rejeite linha se todos os campos essenciais faltarem → registrar em ingestion_errors.

Upload/ETL — Pseudo-código (Node.js + BullMQ)
// POST /api/admin/upload
import formidable from 'formidable';
import { putObject } from './s3'; // ou filesystem
import { sql } from './db';
import { queue } from './queue'; // BullMQ

export default async function handler(req, res) {
  assertAdmin(req.user);

  const { file, filename, mimetype, buffer } = await parseFormidable(req);
  const checksum = md5(buffer);
  const storage_url = await putObject(`ingestions/${checksum}-${filename}`, buffer);

  const { rows } = await sql`
    insert into ingestions (filename, mime_type, storage_url, checksum, uploader_id, status)
    values (${filename}, ${mimetype}, ${storage_url}, ${checksum}, ${req.user.id}, 'queued')
    returning id
  `;
  await queue.add('ingest', { ingestion_id: rows[0].id });

  res.json({ ingestion_id: rows[0].id });
}

// Worker (BullMQ)
import xlsx from 'xlsx';
import { sql } from './db';
import { fetchObject } from './s3';
import { normalizeCompany, normalizePort, hashShipment } from './normalize';

queue.process('ingest', async (job) => {
  const { ingestion_id } = job.data;
  await sql`update ingestions set status='processing', started_at=now() where id=${ingestion_id}`;

  const file = await fetchObject(/* storage_url from DB */);
  const wb = xlsx.read(file, { type: 'buffer' });
  const ws = wb.Sheets[wb.SheetNames[0]];
  const rows = xlsx.utils.sheet_to_json(ws, { defval: null });

  let ok = 0, failed = 0;

  for (let i = 0; i < rows.length; i++) {
    const r = mapColumns(rows[i]); // mapeia cabeçalhos do seu Excel para campos canônicos
    try {
      const importerId = await upsertCompany(r.importer_name, 'importer', r.importer_country);
      const exporterId = await upsertCompany(r.exporter_name, 'exporter', r.exporter_country);
      const loadPortId  = await upsertPort(r.loading_port, r.loading_country);
      const destPortId  = await upsertPort(r.destination_port, r.destination_country);

      const uid = hashShipment({
        shipment_no: r.shipment_no, ets: r.ets, eta: r.eta,
        importerId, exporterId, loadPortId, destPortId
      });

      await sql`
        insert into shipments (
          shipment_uid, shipment_no, ets, eta, cargo_type,
          importer_id, exporter_id, forwarder_id, carrier_id,
          loading_port_id, destination_port_id, hs_code,
          teus, containers, gross_weight_kg, volumes,
          loading_country, ingestion_id, raw_row_hash
        )
        values (
          ${uid}, ${r.shipment_no}, ${r.ets}, ${r.eta}, ${r.cargo_type},
          ${importerId}, ${exporterId}, ${null}, ${null},
          ${loadPortId}, ${destPortId}, ${r.hs_code},
          ${r.teus}, ${r.containers}, ${r.gross_weight_kg}, ${r.volumes},
          ${r.loading_country}, ${ingestion_id}, ${md5(JSON.stringify(r))}
        )
        on conflict (shipment_uid) do nothing
      `;
      ok++;
    } catch (e) {
      failed++;
      await sql`
        insert into ingestion_errors (ingestion_id, row_number, error_code, error_message, raw_payload)
        values (${ingestion_id}, ${i+1}, ${e.code || 'ERR'}, ${String(e)}, ${rows[i]})
      `;
    }
  }

  await sql`
    update ingestions
    set status='done', rows_total=${ok+failed}, rows_ok=${ok}, rows_failed=${failed}, finished_at=now()
    where id=${ingestion_id}
  `;
});
